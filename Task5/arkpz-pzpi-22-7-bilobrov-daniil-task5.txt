Розгорнути програмну систему, перевірити її функціональність та налаштувати для безперебійної роботи. Забезпечити коректне взаємодія з іншими компонентами та продемонструвати стабільність роботи розгорнутої системи в реальних умовах.



2	ХІД РОБОТИ

У процесі виконання лабораторної роботи я підготував свій проєкт до роботи в Docker. Було виконано такі основні дії:

•	Створення контейнерів: Розроблено Dockerfile для бекенд-частини додатку, в який додано всі необхідні залежності. На основі цього Dockerfile зібрано Docker-образ для запуску додатку в контейнері.
•	Налаштування середовища Docker Compose: Сконфігуровано docker-compose.yml для одночасного запуску бекенд-частини та Microsoft SQL Server. Налаштовано сервіси для взаємодії додатку з базою даних, визначено мережу для зв'язку контейнерів, а також прописано змінні середовища (наприклад, ім'я користувача, пароль та назва бази даних).
•	Робота з базою даних: Microsoft SQL Server налаштовано в Docker-контейнері таким чином, щоб база даних автоматично створювалась під час запуску контейнера. Перевірено успішне підключення FastAPI до бази даних.
•	Перевірка функціоналу: Запущено додаток за допомогою Docker Compose, виконано тестування API та перевірено правильну взаємодію з базою даних.
•	Підсумок: Завдяки контейнеризації проект отримав мобільність і можливість швидкого розгортання на різних пристроях, що значно спростило налаштування середовища та зробило його незалежним від конкретних системних конфігурацій.

ВИСНОВКИ


В результаті виконання цієї роботи було створено контейнеризовану інфраструктуру для проєкту за допомогою Docker. Це дозволило розгорнути проєкт разом із базою даних Microsoft SQL Server у контейнерах, що забезпечує портативність і зручність запуску на різних пристроях. Такий підхід значно спрощує налаштування середовища, знижує ймовірність помилок конфігурації та сприяє більш ефективному управлінню додатком в різних середовищах. Використання Docker дозволяє також легко масштабувати та інтегрувати додаток у різні екосистеми, спрощуючи процес розгортання й експлуатації.

Фрагменти коду для розгортання програми в Docker

networks:
  demoappnetowrk: 

services:
 mssql-container:
    image: mcr.microsoft.com/mssql/server:latest
    container_name: mssql-container
    environment:
      - ACCEPT_EULA=Y   # Accept the End-User License Agreement
      - SA_PASSWORD=MyDemoPassword@2022 # Set the 'sa' user password
    ports:
     - "8002:1433"
    networks:
        - demoappnetowrk
 pivogo.api:
    image: ${DOCKER_REGISTRY-}pivogoapi
    build:
      context: .
      dockerfile: PivoGo.Api/Dockerfile
    depends_on:
    - mssql-container
    networks:
        - demoappnetowrk

services:
  pivogo.api:
    environment:
      - ASPNETCORE_ENVIRONMENT=Development
      - ASPNETCORE_HTTP_PORTS=80
    ports:
      - "80"
    volumes:
      - ${APPDATA}/Microsoft/UserSecrets:/home/app/.microsoft/usersecrets:ro
      - ${APPDATA}/ASP.NET/Https:/home/app/.aspnet/https:ro

# См. статью по ссылке https://aka.ms/customizecontainer, чтобы узнать как настроить контейнер отладки и как Visual Studio использует этот Dockerfile для создания образов для ускорения отладки.

# Этот этап используется при запуске из VS в быстром режиме (по умолчанию для конфигурации отладки)
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS base
USER app
WORKDIR /app
EXPOSE 8080


# Этот этап используется для сборки проекта службы
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
ARG BUILD_CONFIGURATION=Release
WORKDIR /src
COPY ["PivoGo.Api/PivoGo.Api.csproj", "PivoGo.Api/"]
COPY ["PivoGo.Application/PivoGo.Application.csproj", "PivoGo.Application/"]
COPY ["PivoGo.Domain/PivoGo.Domain.csproj", "PivoGo.Domain/"]
COPY ["EmailService/EmailService.csproj", "EmailService/"]
COPY ["PivoGo.Infrastructure/PivoGo.Infrastructure.csproj", "PivoGo.Infrastructure/"]
RUN dotnet restore "./PivoGo.Api/PivoGo.Api.csproj"
COPY . .
WORKDIR "/src/PivoGo.Api"
RUN dotnet build "./PivoGo.Api.csproj" -c $BUILD_CONFIGURATION -o /app/build

# Этот этап используется для публикации проекта службы, который будет скопирован на последний этап
FROM build AS publish
ARG BUILD_CONFIGURATION=Release
RUN dotnet publish "./PivoGo.Api.csproj" -c $BUILD_CONFIGURATION -o /app/publish /p:UseAppHost=false

# Этот этап используется в рабочей среде или при запуске из VS в обычном режиме (по умолчанию, когда конфигурация отладки не используется)
FROM base AS final
WORKDIR /app
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "PivoGo.Api.dll"]
